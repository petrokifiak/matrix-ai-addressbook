# План розробки фінального проєкту «Персональний помічник» (Trello Tasks)

Цей документ містить детальний план завдань для організації роботи команди. Завдання розбиті на етапи відповідно до офіційних вимог до проєкту.

---

## 📋 Етап 1: Організація та інфраструктура (Team Lead / Scrum Master)

- **Task 1.1: Створення спільного репозиторію**  
  *Опис:* Створити та налаштувати репозиторій на GitHub, додати `.gitignore`, `README.md` та надати доступ усім членам команди.
- **Task 1.2: Налаштування Git Flow та правил співпраці**  
  *Опис:* Встановити правила створення гілок (feature-branches), оформлення комітів та проведення Code Review через Pull Requests.
- **Task 1.3: Створення Trello дошки проекту**  
  *Опис:* Створити дошку в Trello (колонки: Backlog, To Do, In Progress, Review, Done) та перенести таски.
- **Task 1.4: Розподіл ролей у команді**  
  *Опис:* Визначити обов'язки для ролей Team Lead, Scrum Master та розробників для координації спринтів.

---

## 🗄️ Етап 2: Зберігання даних (Storage & Persistence)

- **Task 2.1: Збереження контактів та нотаток на диск**  
  *Опис:* Реалізувати механізм серіалізації (pickle) контактної книги та нотатника у файли в директорії користувача.
- **Task 2.2: Відновлення даних при старті**  
  *Опис:* Реалізувати завантаження збережених контактів і нотаток під час запуску програми та створення нових сховищ, якщо файли відсутні.
- **Task 2.3: Автоматичне збереження при завершенні**  
  *Опис:* Забезпечити гарантоване збереження всіх змін у файли при виході користувача з програми (команди `close`, `exit`).

---

## 📞 Етап 3: Модуль «Книга контактів» (Contacts Management)

- **Task 3.1: Моделі полів контакту (Field, Name, Phone, Email, Address, Birthday)**  
  *Опис:* Створити базові та спеціалізовані класи полів із інкапсуляцією даних.
- **Task 3.2: Валідація номера телефону**  
  *Опис:* Реалізувати перевірку формату номера телефону (рівно 10 цифр) та повідомлення користувача при помилці.
- **Task 3.3: Валідація електронної пошти**  
  *Опис:* Реалізувати перевірку коректності формату email через регулярні вирази з інформативним повідомленням про помилку.
- **Task 3.4: Валідація дати народження**  
  *Опис:* Забезпечити перевірку правильності формату дати `DD.MM.YYYY` та валідності значень.
- **Task 3.5: Додавання контакту з повними даними**  
  *Опис:* Реалізувати команду `add` для додавання імені, телефону, email, адреси та дня народження.
- **Task 3.6: Редагування даних контакту**  
  *Опис:* Реалізувати зміну телефону (`change`), додавання/зміну email (`add-email`), адреси (`add-address`) та дня народження (`add-birthday`).
- **Task 3.7: Видалення контакту**  
  *Опис:* Реалізувати команду `delete` для видалення запису контакту з адресної книги за ім'ям.
- **Task 3.8: Пошук контактів за критеріями**  
  *Опис:* Реалізувати команду `search-contacts` для пошуку контактів за підрядком в імені, телефоні, email чи адресі.
- **Task 3.9: Сповіщення про дні народження на N днів**  
  *Опис:* Реалізувати команду `birthdays [days]` для виведення списку контактів, у яких день народження припадає на наступні N днів (з перенесенням вихідних на понеділок).

---

## 📝 Етап 4: Модуль «Нотатки» (Notes Management)

- **Task 4.1: Моделі нотатки та блокнота (Note, NoteBook)**  
  *Опис:* Створити класи `Note` (з полями id, title, content, tags) та `NoteBook` (колекція нотаток із методами управління).
- **Task 4.2: Створення та додавання нотатки**  
  *Опис:* Реалізувати команду `add-note` для створення нотатки із заголовком та текстом.
- **Task 4.3: Перегляд усіх нотаток**  
  *Опис:* Реалізувати команди `all-notes` / `show-notes` для відображення списку всіх збережених нотаток.
- **Task 4.4: Пошук нотаток за змістом**  
  *Опис:* Реалізувати команду `search-notes` для пошуку за ключовими словами/підрядками в заголовку або тексті нотатки.
- **Task 4.5: Редагування нотатки**  
  *Опис:* Реалізувати команду `edit-note` для оновлення тексту існуючої нотатки за її ідентифікатором або заголовком.
- **Task 4.6: Видалення нотатки**  
  *Опис:* Реалізувати команду `delete-note` для видалення нотатки за її ідентифікатором або назвою.

---

## ⭐ Етап 5: Обов'язковий додатковий функціонал (+10 балів)

- **Task 5.1: Додавання тегів до нотаток**  
  *Опис:* Реалізувати підтримку тегів (ключових слів) у нотатках та команду `add-tag` для додавання тегів до існуючих або нових нотаток.
- **Task 5.2: Пошук нотаток за тегами**  
  *Опис:* Реалізувати команду `search-by-tag` для вибірки всіх нотаток, що містять вказаний тег.
- **Task 5.3: Сортування нотаток за тегами**  
  *Опис:* Реалізувати команду `sort-notes` для сортування нотаток за кількістю або алфавітом тегів.

---

## 🚀 Етап 6: Підготовка до здачі та дедлайни (Team Lead)

- **Task 6.1: Внутрішнє тестування та узгодження (Четвер, 21:00)**  
  *Опис:* Провести фінальне тестування функціоналу, покрити код unit/integration тестами та передати результат Team Lead.
- **Task 6.2: Створення документації користувача**  
  *Опис:* Оновити `README.md` або GitHub Wiki з повним списком команд, синтаксисом та прикладами використання.
- **Task 6.3: Підготовка презентації проекту**  
  *Опис:* Створити слайди для Демо-дня з демонстрацією можливостей бота та командного процесу.
- **Task 6.4: Передача проєкту ментору у Slack (П'ятниця, до 19:00)**  
  *Опис:* Надіслати ментору узгоджене повідомлення з посиланнями на репозиторій, документацію та презентацію.
- **Task 6.5: Опрацювання зворотного зв'язку ментора**  
  *Опис:* Оперативно внести виправлення у разі отримання коментарів на доопрацювання.
- **Task 6.6: Завантаження ZIP-архіву в LMS (Понеділок, 10:00–19:00)**  
  *Опис:* Кожному учаснику завантажити архів проєкту у форматі `.zip` разом із посиланням на GitHub у кабінет LMS.
